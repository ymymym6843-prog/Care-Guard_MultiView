## 1. 프로젝트 소개

### 1.1 SENTIO 개요

**SENTIO**는 요양병원 및 요양시설의 대기실에서 실시간으로 낙상 사고를 감지하는 AI 기반 모니터링 시스템입니다. 고령 환자와 보호자의 안전을 지키기 위해 카메라 영상을 분석하여 낙상 위험을 조기에 감지하고, 의료진에게 즉시 알림을 전송합니다.

**핵심 가치**
- **골든타임 확보**: 낙상 발생 후 3~10초 내 즉시 알림으로 신속 대응 가능
- **프라이버시 보호**: 스켈레톤 모드로 영상 없이 좌표만 전송, 개인정보 보호
- **다중 인원 동시 감지**: 대기실의 여러 사람을 동시에 모니터링
- **다중공간 관리**: 복도, 대기실 등 공간별 카메라 배정 및 독립 모니터링/통계/리포트
- **높은 정확도**: F1 94.9%, Recall 95.2%, Precision 94.6% (424개 영상 벤치마크)

### 1.2 기술 차별점

#### AI 하이브리드 접근
- **YOLO11 포즈 추정**: 실시간 30fps로 사람의 신체 키포인트(관절 좌표) 추출
- **GRU 시퀀스 분류기**: 30프레임 시계열 데이터를 분석하여 낙상 패턴 학습
- **규칙 기반 엔진**: 각도, 자세, 속도 등 물리적 규칙으로 오탐 방지

#### 프라이버시 보호 3단계
1. **Full Mode (원본 영상)**: 관리자용 전체 화면 표시
2. **Blur Mode (블러 처리)**: 얼굴 및 신체 흐림 처리
3. **Skeleton Mode (스켈레톤)**: 검은 배경에 뼈대만 표시, 영상 서버 밖으로 전송 안 됨

#### 실시간 스트리밍 아키텍처
```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐     ┌──────────────┐
│  웹캠/RTSP  │────▶│ YOLO11 Pose  │────▶│ GRU 분류기  │────▶│  규칙 엔진   │
└─────────────┘     └──────────────┘     └─────────────┘     └──────────────┘
                            │                                         │
                            │ 키포인트 좌표                           │ 이벤트
                            ▼                                         ▼
                    ┌──────────────┐                         ┌──────────────┐
                    │  WebSocket   │◀───────────────────────│  Event DB    │
                    └──────────────┘                         └──────────────┘
                            │
                            ▼
                    ┌──────────────┐
                    │  React UI    │ (Canvas 렌더링)
                    │  + MJPEG     │
                    └──────────────┘
```

**데이터 흐름**
1. 카메라가 30fps 원본 영상을 MJPEG로 직접 송출 (AI 처리와 독립)
2. YOLO11이 각 프레임에서 사람의 17개 키포인트 추출
3. GRU 모델이 최근 30프레임의 키포인트 시퀀스를 분석하여 낙상 확률 계산
4. 규칙 엔진이 각도, 속도, 지속시간 등을 종합하여 최종 판단
5. WebSocket을 통해 프론트엔드로 bbox, 키포인트, 상태 정보 전송
6. React UI가 Canvas에 실시간으로 오버레이 렌더링

### 1.3 시스템 아키텍처

**기술 스택**
- **Backend**: FastAPI (Python 3.11), PostgreSQL, SQLAlchemy
- **Frontend**: React 18, TypeScript, Vite 6, Tailwind CSS 4
- **AI/CV**: YOLO11 (Ultralytics), MediaPipe, ONNX Runtime, GRU Neural Network
- **Streaming**: MJPEG (30fps) + WebSocket (AI 오버레이)
- **Deployment**: Docker Compose, Nginx

**포트 구성**
- Backend API: **8001** (PORT 환경변수)
- Frontend Dev: 5173 (Vite, 프록시로 8001 연결)
- Production: 80/443 (Nginx reverse proxy)

## 2. 시스템 요구사항 및 설치

### 2.1 하드웨어 요구사항

| 구분 | 최소 사양 | 권장 사양 |
|------|----------|----------|
| **CPU** | Intel i5 4코어 이상 | Intel i7/Ryzen 7 8코어 이상 |
| **RAM** | 8GB | 16GB 이상 |
| **GPU** | 통합 그래픽 (CPU 처리) | NVIDIA GPU + CUDA 12.x (권장) |
| **저장공간** | 10GB 이상 여유 공간 | SSD 20GB 이상 |
| **카메라** | 웹캠 720p 이상 | IP 카메라 1080p 30fps |
| **네트워크** | 유선 100Mbps | 유선 1Gbps |

**GPU 사용 시 장점**
- YOLO11 추론 속도 5~10배 향상 (15ms → 3ms per frame)
- 다중 인원 감지 시에도 30fps 유지
- CPU 부하 감소로 시스템 안정성 향상

### 2.2 소프트웨어 요구사항

- **운영체제**: Windows 10/11, Ubuntu 20.04+, macOS 12+
- **Python**: 3.11 이상
- **Node.js**: 20 이상
- **Docker**: 최신 버전 (선택 사항, 배포 시 권장)
- **CUDA Toolkit**: 12.x (GPU 사용 시)
- **웹 브라우저**: Chrome/Edge 최신 버전 (WebSocket 지원 필수)

### 2.3 설치 방법

#### 방법 1: Docker Compose (권장)

가장 간단하고 안정적인 배포 방법입니다.

```bash
# 1. 프로젝트 클론
git clone https://github.com/your-org/sentio.git
cd sentio

# 2. 환경 변수 설정
cp .env.example .env
# .env 파일 편집 (JWT_SECRET_KEY, DATABASE_URL 등 설정)

# 3. Docker Compose로 전체 시스템 시작
docker compose up -d --build

# 4. 브라우저에서 http://localhost 접속
```

#### 방법 2: 로컬 개발 환경

개발 및 디버깅 용도로 사용합니다.

```bash
# 1. 백엔드 설치
cd backend
python -m venv venv

# Windows
venv\Scripts\activate

# Mac/Linux
source venv/bin/activate

pip install -r requirements.txt

# 2. 프론트엔드 설치
cd ../frontend
npm install

# 3. 환경 변수 설정
cd ..
cp .env.example .env
# .env 파일 편집

# 4. 백엔드 실행 (터미널 1)
cd backend
uvicorn app.main:app --reload --host 0.0.0.0 --port 8001

# 5. 프론트엔드 실행 (터미널 2)
cd frontend
npm run dev

# 6. 브라우저에서 http://localhost:5173 접속
```

#### 방법 3: 배치 파일 (Windows)

프로젝트에 포함된 `run_dev.bat`를 실행하면 백엔드와 프론트엔드가 자동으로 시작됩니다.

```bash
# 더블클릭 또는 명령 프롬프트에서
run_dev.bat
```

### 2.4 환경 변수 설정

`.env` 파일의 주요 설정 항목:

```env
# 서버 설정
HOST=0.0.0.0
PORT=8001
DEBUG=false

# 데이터베이스 (PostgreSQL)
DATABASE_URL=postgresql+asyncpg://user:password@localhost/sentio

# 보안 (반드시 변경!)
JWT_SECRET_KEY=your-super-secret-key-change-this-in-production

# 프론트엔드 URL (CORS)
FRONTEND_URL=http://localhost:5173

# 낙상 감지 임계값
FALL_WARNING_SECONDS=3.0   # 주의 알림 활성화 시간
FALL_DANGER_SECONDS=10.0   # 위험 알림 활성화 시간

# Web Push 알림 (선택, scripts/generate_secrets.py로 생성)
VAPID_PUBLIC_KEY=your-vapid-public-key
VAPID_PRIVATE_KEY=your-vapid-private-key
```

**보안 주의사항**
- `JWT_SECRET_KEY`는 강력한 난수로 설정하고 절대 공개하지 마세요
- 프로덕션 환경에서는 `DEBUG=false`로 설정
- `DATABASE_URL`은 외부 노출되지 않도록 방화벽 설정

## 3. 시작하기

### 3.1 최초 관리자 계정 생성

시스템에 처음 접속하면 **자동으로 관리자 계정 생성 페이지**가 표시됩니다.

1. 브라우저에서 `http://localhost:5173` (또는 배포 URL) 접속
2. "관리자 계정 생성" 페이지에서 다음 정보 입력
   - **사용자명**: 영문/숫자 조합 (예: admin)
   - **비밀번호**: 8자 이상, 영문+숫자+특수문자 조합 권장
   - **이메일**: 알림 수신용 이메일 주소
   - **전체 이름**: 실명 입력
3. "계정 생성" 버튼 클릭
4. 자동으로 로그인 페이지로 이동

### 3.2 로그인

1. 로그인 페이지에서 사용자명과 비밀번호 입력
2. "로그인" 버튼 클릭
3. 최초 로그인 시 **개인정보 수집 및 이용 동의** 팝업 표시
   - 영상 데이터 처리 목적 및 보유 기간 안내
   - "동의" 버튼 클릭하여 진행
4. 대시보드로 자동 이동

**로그인 세션**
- Access Token: 8시간 유효 (HttpOnly 쿠키)
- Refresh Token: 7일 유효 (자동 갱신)
- 7일 이상 미접속 시 재로그인 필요

## 4. 공간(Room) 관리

SENTIO는 다중공간 시스템을 지원합니다. 복도, 대기실A, 302호 등 여러 공간에 카메라를 배정하고 공간별로 독립적으로 모니터링할 수 있습니다.

### 4.1 공간 전환

사이드바 상단의 **공간 드롭다운**에서 모니터링할 공간을 선택합니다:

- **전체 공간**: 모든 카메라와 이벤트를 한 화면에서 확인
- **개별 공간 (예: 복도, 대기실A)**: 해당 공간에 배정된 카메라만 표시

#### 공간별 자동 필터링

공간을 선택하면 다음 항목이 자동으로 필터링됩니다:

| 항목 | 필터링 방식 |
|------|-----------|
| **대시보드 영상** | 해당 공간의 카메라만 표시 |
| **상태 카드** | 해당 공간의 인원만 집계 |
| **메트릭스** | 해당 공간의 인물 정보만 표시 |
| **이벤트 로그** | 해당 공간의 이벤트만 표시 |
| **통계** | 해당 공간의 데이터 기준 차트 생성 |
| **리포트** | 해당 공간 기준 리포트 생성 |

### 4.2 공간 생성 및 카메라 배정

관리자 권한으로 다음 API를 통해 공간을 관리합니다:

```bash
# 공간 생성
POST /api/rooms  {"name": "대기실A", "description": "1층 정문 근처 대기실"}

# 카메라 배정
PUT /api/rooms/1/cameras  {"camera_ids": ["cam0", "cam1"]}

# 공간 목록 조회
GET /api/rooms
```

### 4.3 활용 사례

- **대기실 모니터링**: 대기실 전용 카메라를 배정하여 대기 환자 집중 모니터링
- **복도 감시**: 복도 카메라를 별도 공간으로 분리하여 이동 중 낙상 감지
- **병실별 관리**: 병실마다 카메라를 배정하여 개별 환자 케어
- **전체 현황 파악**: "전체 공간" 선택으로 시설 전체 상황 한눈에 확인

## 5. 대시보드 사용법

### 5.1 실시간 영상 모니터링

#### 5.1.1 카메라 시작/중지

- **시작 버튼**: 클릭 시 백엔드에서 웹캠 또는 RTSP 카메라 연결, 실시간 영상 스트리밍 시작
- **중지 버튼**: 스트리밍 및 AI 감지 중단
- **전체화면 버튼**: 영상을 전체화면으로 확대 (ESC로 종료)

#### 5.1.2 프라이버시 모드 3단계

대시보드 우측 상단의 **"프라이버시 모드"** 드롭다운에서 선택:

| 모드 | 설명 | 용도 |
|------|------|------|
| **원본 (Full)** | MJPEG 원본 영상 + Canvas 오버레이 | 관리자 전용, 상세 확인 |
| **블러 (Blur)** | MJPEG 블러 처리 + Canvas 오버레이 | 일반 직원용, 개인정보 보호 |
| **스켈레톤 (Skeleton)** | 검은 배경 + Canvas 스켈레톤만 | 최고 수준 프라이버시, 공개 모니터 |

**기술 상세**
- **스켈레톤 모드**: 영상이 서버 밖으로 전송되지 않음. WebSocket으로 키포인트 좌표만 수신하여 Canvas에 뼈대 렌더링
- **블러 모드**: 서버에서 실시간 가우시안 블러 필터 적용 (얼굴 및 신체 흐림 처리)
- **원본 모드**: MJPEG 스트림 그대로 표시, AI 오버레이(bbox, 키포인트, 텍스트) 추가

#### 5.1.3 AI 오버레이 정보

영상 위에 실시간으로 표시되는 정보:

- **Bounding Box (박스)**: 감지된 사람 주위에 색상별 박스
  - 녹색: 안전(NORMAL)
  - 노란색: 주의(WARNING, 3초 이상 이상 자세)
  - 빨간색: 위험(DANGER, 10초 이상 또는 낙상 감지)
- **키포인트 (관절)**: 17개 COCO 키포인트 (코, 눈, 귀, 어깨, 팔꿈치, 손목, 엉덩이, 무릎, 발목)
- **스켈레톤 라인**: 키포인트를 연결한 뼈대 구조
- **텍스트 정보**: ID, 자세, 낙상 확률, ML/규칙 점수

### 5.2 상태 카드

대시보드 우측 상단에 현재 시스템 상태를 한눈에 표시:

#### 5.2.1 상태 등급 (3단계)

| 상태 | 색상 | 조건 | 대응 |
|------|------|------|------|
| **안전** | 녹색 | 모든 인원 정상 자세 | 정상 모니터링 지속 |
| **주의** | 노란색 | 1명 이상 3초 이상 이상 자세 (앉기, 구부림 등) | 영상 주시, 준비 태세 |
| **위험** | 빨간색 | 1명 이상 10초 이상 이상 자세 또는 낙상 감지 | 즉시 현장 확인 및 조치 |

#### 5.2.2 통계 정보

- **감지된 인원 수**: 현재 프레임에서 YOLO11이 감지한 총 인원
- **경고 중인 인원**: 주의 또는 위험 상태인 인원 수
- **오늘 낙상 이벤트**: 당일 감지된 총 낙상 이벤트 수

### 5.3 메트릭스 카드 (인물별 상세 정보)

감지된 각 인물에 대한 실시간 정보 표시:

```
┌─────────────────────────────────────────────────────┐
│ 👤 Person #1 (Track ID: 001)                        │
├─────────────────────────────────────────────────────┤
│ 자세: Standing                                      │
│ 낙상 확률: 5.2%                                     │
│ 규칙 점수: 0.02 | ML 점수: 0.05                    │
│ 각도 (엉덩이-어깨): 85°                            │
│ 지속시간: 0.3초                                     │
│ 상태: NORMAL (녹색)                                 │
└─────────────────────────────────────────────────────┘
```

**메트릭스 항목 설명**

| 항목 | 설명 | 정상 범위 |
|------|------|----------|
| **자세 (Posture)** | Standing, Sitting, Crouching, Lying, Unknown | Standing/Sitting |
| **낙상 확률** | GRU ML 모델 출력 (0~100%) | <20% |
| **규칙 점수** | 규칙 기반 엔진 점수 (0~1) | <0.20 |
| **ML 점수** | ML 모델 점수 (0~1) | <0.20 |
| **각도** | 엉덩이-어깨 중심선과 수직선 각도 | 60~90° |
| **지속시간** | 현재 자세 유지 시간 (초) | - |

**주의 사항**
- 낙상 확률 > 70% 또는 규칙/ML 점수 > 0.70: 위험 신호
- 지속시간 > 3초 + 이상 자세: WARNING 상태 진입
- 지속시간 > 10초 + 이상 자세: DANGER 상태 진입

### 5.5 감지 설정

대시보드 하단의 "감지 설정" 패널에서 실시간 조정 가능:

#### 5.5.1 임계값 설정

| 설정 | 기본값 | 설명 |
|------|--------|------|
| **주의 알림 시간** | 3초 | 이상 자세 지속 시 WARNING 상태 진입 시간 |
| **위험 알림 시간** | 10초 | 이상 자세 지속 시 DANGER 상태 진입 시간 |

**조정 팁**
- 민감도를 높이려면: 주의 2초, 위험 7초
- 오탐을 줄이려면: 주의 5초, 위험 15초

#### 5.5.2 감도 설정

| 감도 | 낙상 확률 임계값 | 규칙 점수 임계값 | 설명 |
|------|-----------------|-----------------|------|
| **낮음** | 80% | 0.80 | 매우 확실한 낙상만 감지 (오탐 최소) |
| **보통** | 70% | 0.70 | 권장 설정 (F1 94.9% 벤치마크 기준) |
| **높음** | 60% | 0.60 | 잠재적 위험까지 감지 (오탐 증가 가능) |

#### 5.5.3 알림 설정

- **소리 알림**: 위험 상태 시 비프음 재생 (브라우저 자동재생 정책 허용 필요)
- **음성 알림 (TTS)**: "낙상이 감지되었습니다. 즉시 확인하세요." 음성 안내
- **푸시 알림**: Web Push API로 브라우저 알림 전송 (권한 허용 필요)
- **진동**: 모바일 기기에서 진동 피드백 (지원 기기만)

**알림 설정 권장**
- 간호사실: 소리 + 음성 + 푸시 모두 활성화
- 공용 모니터: 푸시만 활성화 (소음 방지)

## 6. 낙상 감지 대응 절차

### 6.1 3단계 알림 체계

SENTIO는 위험도에 따라 3단계로 점진적 알림을 제공합니다.

```
[정상 상태] ──────▶ [주의 상태] ──────▶ [위험 상태]
  (녹색)              (노란색)           (빨간색)
   0~3초               3~10초            10초 이상
                                        또는 낙상 감지
```

#### 10.1.1 주의 상태 (WARNING)

**진입 조건**
- 이상 자세(앉기, 구부림, 누움) 3초 이상 지속
- 낙상 확률 40~70%

**화면 표시**
- Bounding Box: 노란색
- 상태 카드: "주의" (노란색 배경)
- 이벤트 로그: "WARNING (3.2초)" 기록

**대응 지침**
1. 영상 주시하며 상황 관찰
2. 의도적인 행동(물건 줍기, 신발 끈 묶기 등)인지 확인
3. 10초 이내 정상 자세로 복구되는지 확인
4. 필요 시 대기실로 이동 준비

#### 10.1.2 위험 상태 (DANGER)

**진입 조건**
- 이상 자세 10초 이상 지속
- 낙상 확률 70% 이상 (GRU ML 모델)
- 규칙 점수 0.70 이상

**화면 표시**
- Bounding Box: 빨간색 (두꺼운 선)
- 상태 카드: "위험" (빨간색 배경, 깜빡임)
- **위험 다이얼로그 모달**: 화면 중앙에 대형 팝업 표시
- 알림음: 비프음 연속 재생 (3회)
- 음성 안내: "낙상이 감지되었습니다. 즉시 확인하세요."
- 푸시 알림: 브라우저 알림 + 진동 (모바일)

**대응 지침 (즉시 조치 필요)**
1. **즉시 현장으로 이동** (골든타임 10초 내)
2. 환자 의식 확인
3. 필요 시 119 신고
4. 이동 금지 (척추 손상 가능성)
5. 바이탈 체크 (맥박, 호흡, 혈압)
6. 의사에게 보고

#### 10.1.3 위험 다이얼로그 확인

위험 상태 진입 시 대형 모달 팝업 표시:

```
┌────────────────────────────────────────────────┐
│  ⚠️  낙상 위험 감지!                            │
├────────────────────────────────────────────────┤
│                                                │
│  Person #2에서 낙상이 감지되었습니다.          │
│  즉시 현장을 확인하세요.                       │
│                                                │
│  시간: 14:35:22                                │
│  위치: 대기실 좌측 (Safe-Zone A)               │
│  지속시간: 12.3초                              │
│  낙상 확률: 87%                                │
│                                                │
│          [확인하러 가기] [무시]                │
│                                                │
└────────────────────────────────────────────────┘
```

**버튼 동작**
- **확인하러 가기**: 알림 해제 + 이벤트 로그에 "확인됨" 기록
- **무시**: 알림 해제 (비상 상황 아닐 시)

**자동 해제**
- 환자가 정상 자세로 복구 시 자동으로 모달 닫힘
- 30초 이내 조치하지 않으면 알림 재전송

### 6.2 오탐 방지 메커니즘

SENTIO는 다음과 같은 기술로 오탐(False Positive)을 방지합니다.

#### 8.2.1 Quick Recovery Detection
- 의도적으로 누웠다가 5초 내 일어서는 경우 → 낙상 아님
- 예: 물건 줍기, 신발 끈 묶기, 요가 동작

#### 8.2.2 Standing FP Post-EMA Filter
- 서 있는 자세 + 각도 75° 이상 + 규칙 점수 0.20 미만 + ML 점수 0.90 미만 → 감지 취소
- 예: 키가 큰 사람, 팔을 들어올린 동작

#### 6.2.3 Controlled Movement Post-Fall
- 낙상 후 10프레임 내 속도 분산 0.0005 미만 + 자세가 LYING 아님 → 오탐 해제
- 예: 천천히 앉는 동작

#### 6.2.4 Multi-frame Accumulation
- 가시성 0.3~0.5 (부분 가려짐) 상태에서는 3프레임 연속 점수 ≥0.35일 때만 감지
- 예: 물건에 가려진 상태, 카메라 각도 문제

### 6.3 실제 대응 시나리오

#### 시나리오 1: 후방 낙상 (의자에서 뒤로 넘어짐)

1. **0초**: 환자가 의자에 앉아 있음 (SITTING, 녹색)
2. **1.2초**: 뒤로 기울어짐 시작 (각도 60°, 낙상 확률 45%, CROUCHING)
3. **2.5초**: 바닥에 눕기 시작 (각도 30°, 낙상 확률 82%, LYING)
4. **3.0초**: WARNING 상태 진입 (노란색 박스, "주의" 카드)
5. **3.5초**: ML 모델 확신도 87% (연속 프레임 점수 누적)
6. **3.8초**: DANGER 상태 즉시 진입 (빨간색 박스, 위험 다이얼로그 표시, 알림음)
7. **간호사 대응**: 10초 내 현장 도착, 환자 의식 확인, 이동 금지, 의사 보고

#### 시나리오 2: 물건 줍기 (오탐 방지)

1. **0초**: 환자가 서 있음 (STANDING, 녹색)
2. **1.0초**: 허리 숙이기 시작 (각도 70°, 낙상 확률 15%, CROUCHING)
3. **2.5초**: 물건 주움 (각도 40°, 낙상 확률 35%, CROUCHING)
4. **4.2초**: 다시 일어남 (각도 85°, 낙상 확률 5%, STANDING)
5. **결과**: Quick Recovery Detection 작동 → 낙상 아님 판단, WARNING 진입하지 않음

#### 시나리오 3: 의도적 누움 (요가 동작)

1. **0초**: 환자가 서 있음 (STANDING)
2. **2.0초**: 천천히 바닥에 눕기 시작 (속도 분산 0.0002, CROUCHING)
3. **5.0초**: 완전히 누움 (LYING, 낙상 확률 20%)
4. **8.0초**: WARNING 상태 진입 (노란색 박스)
5. **12초**: Controlled Movement Post-Fall 필터 작동 → 의도적 동작 판단, DANGER 진입하지 않음

### 10.3 예상 Q&A 및 답변

#### Q1: "정확도가 94.9%라고 했는데, 벤치마크는 어떻게 했나요?"

**답변**
> "AIHub 낙상 데이터셋 424개 영상(BY 100, FY 100, SY 100, N 100, 추가 24개)으로 종합 벤치마크를 수행했습니다. 실제 요양병원 환경을 시뮬레이션한 영상으로, BY(후방낙상) 99%, FY(전방낙상) 97%, SY(측면낙상) 91%, N(정상행동) 83%의 Recall을 달성했습니다. 벤치마크 스크립트는 `scripts/comprehensive_benchmark.py`에서 확인 가능합니다."

#### Q2: "오탐(False Positive)은 어떻게 방지하나요?"

**답변**
> "3가지 메커니즘으로 오탐을 방지합니다. 첫째, Quick Recovery Detection으로 5초 내 복구되면 의도적 행동으로 판단. 둘째, Standing FP Post-EMA Filter로 서 있는 자세에서 각도 75도 이상이고 ML 점수 0.90 미만이면 감지 취소. 셋째, Controlled Movement Post-Fall 필터로 낙상 후 속도 분산이 낮으면 의도적 동작으로 판단합니다. 실제 벤치마크에서 False Positive는 17건(4.0%)으로 매우 낮습니다."

#### Q3: "프라이버시는 어떻게 보장하나요?"

**답변**
> "스켈레톤 모드에서는 원본 영상이 서버 밖으로 전송되지 않습니다. YOLO11이 서버에서 키포인트 좌표만 추출하고, WebSocket으로 17개 점의 (x, y, z) 좌표만 프론트엔드로 전송합니다. 프론트엔드는 Canvas API로 검은 배경에 뼈대만 렌더링합니다. 따라서 얼굴, 신체, 배경 정보가 일절 노출되지 않아 개인정보보호법을 준수합니다."

#### Q4: "GRU 모델은 어떻게 학습했나요?"

**답변**
> "AIHub 낙상 데이터셋 665,574개 샘플(30프레임×99특징)로 학습했습니다. 입력은 30프레임의 키포인트 시퀀스, 출력은 binary 낙상 확률입니다. ONNX Runtime으로 변환하여 추론 속도를 최적화했습니다. 학습 스크립트는 `scripts/training/retrain_gru_enhanced.py`에 있습니다. 참고로 v2로 재학습을 시도했으나 False Positive가 증가하여 v1 원본 모델을 최종 채택했습니다."

#### Q5: "실제 병원에 배포하려면 어떻게 하나요?"

**답변**
> "Docker Compose로 간단히 배포 가능합니다. PostgreSQL, Nginx, go2rtc를 모두 컨테이너로 패키징했고, Let's Encrypt certbot으로 HTTPS 인증서 자동 갱신을 지원합니다. RTSP 카메라 연동도 `go2rtc.yaml` 설정 파일 수정만으로 가능합니다. 프로덕션 배포 가이드는 README.md와 docker-compose.ssl.yml을 참고하시면 됩니다."

#### Q6: "다른 낙상 감지 시스템과의 차별점은?"

**답변**
> "첫째, YOLO11과 GRU 하이브리드 접근으로 규칙 기반의 한계를 극복했습니다. 둘째, MJPEG 스트리밍과 AI 오버레이 분리 아키텍처로 30fps 실시간 처리와 프라이버시 보호를 동시에 달성했습니다. 셋째, 3단계 점진적 알림으로 오탐을 최소화하면서 골든타임을 확보했습니다. 넷째, Safe-Zone 에디터와 통계 대시보드로 운영 최적화를 지원합니다. 시중 제품 대비 정확도가 5-10% 높고, 오픈소스 프로젝트로 커스터마이징이 자유롭습니다."

#### Q7: "GPU 없이도 작동하나요?"

**답변**
> "네, CPU만으로도 작동합니다. YOLO11 Small 모델은 CPU에서도 초당 15-20fps 처리가 가능합니다. 다만 GPU가 있으면 30fps를 안정적으로 유지하고, 다중 인원 감지 시에도 성능 저하가 없습니다. CUDA 12.x 환경에서는 추론 속도가 5-10배 향상됩니다. 개발 환경에서는 CPU로 충분하고, 프로덕션에서는 GPU 권장입니다."

## 10. FAQ 및 문제 해결

### 10.1 로그인 및 인증

#### Q: 비밀번호를 잊어버렸어요.

**A**: 현재 버전에서는 관리자에게 요청하여 비밀번호를 재설정해야 합니다. 관리자는 "관리자 > 사용자 관리"에서 해당 사용자의 "편집" 버튼을 클릭하여 "비밀번호 재설정" 기능을 사용할 수 있습니다.

#### Q: "로그인 세션이 만료되었습니다" 오류가 자주 떠요.

**A**: Refresh Token이 만료된 것입니다(7일 유효). 재로그인하면 됩니다. 자동 로그인을 원하시면 "로그인 유지" 기능이 향후 추가될 예정입니다.

### 10.2 카메라 및 스트리밍

#### Q: "시작" 버튼을 눌렀는데 카메라가 안 켜져요.

**A**: 다음을 확인하세요.
1. 백엔드 서버 실행 확인: http://localhost:8001/docs 접속 가능한지
2. 웹캠 연결 확인: 다른 프로그램(Zoom, Skype)에서 카메라 사용 중인지
3. 브라우저 콘솔 에러 확인: F12 → Console 탭
4. 백엔드 로그 확인: `backend/logs/app.log` 파일 열어보기

**해결 방법**
- Windows: 설정 > 개인정보 > 카메라 권한 허용
- 다른 프로그램 종료 후 재시도
- 백엔드 재시작: Ctrl+C 후 `uvicorn app.main:app --reload --host 0.0.0.0 --port 8001`

#### Q: 영상이 끊기거나 프레임이 떨어져요.

**A**: CPU/GPU 리소스 부족입니다.
1. 다른 프로그램 종료 (크롬 탭 정리)
2. AI 모델을 더 가벼운 것으로 변경: "관리자 > AI 모델 관리"에서 YOLO11n 선택
3. 해상도 낮추기: 웹캠 설정에서 720p로 변경

#### Q: 블러 모드가 안 먹혀요.

**A**: 블러 처리는 백엔드에서 수행되므로, 서버 성능이 낮으면 적용되지 않을 수 있습니다. CPU 사용률이 90% 이상이면 원본 모드로 전환하거나, GPU를 사용하세요.

### 10.3 낙상 감지

#### Q: 정상 상황인데 자꾸 WARNING이 떠요 (오탐).

**A**: 감도를 낮추세요.
1. 대시보드 하단 "감지 설정"에서 감도를 "보통" → "낮음"으로 변경
2. 주의 알림 시간을 3초 → 5초로 증가
3. Safe-Zone 설정에서 의자 영역을 "안전 구역"으로 지정

#### Q: 실제 낙상인데 감지가 안 돼요 (미검출).

**A**: 감도를 높이세요.
1. 감도를 "보통" → "높음"으로 변경
2. 위험 알림 시간을 10초 → 7초로 감소
3. AI 모델을 더 정확한 것으로 변경: YOLO11s → YOLO26s

#### Q: 여러 사람 중 한 명만 감지돼요.

**A**: YOLO11은 최대 10명까지 동시 감지 가능합니다. 만약 감지가 안 되면:
1. 카메라 각도 조정 (정면이 아닌 사람은 키포인트 추출 어려움)
2. 조명 밝기 확인 (너무 어두우면 감지 안 됨)
3. 겹침 현상: 사람들이 너무 가까이 있으면 1명으로 인식될 수 있음

### 10.4 알림 및 소리

#### Q: 소리 알림이 안 나와요.

**A**: 브라우저 자동재생 정책 때문입니다.
1. Chrome: 주소창 좌측 자물쇠 아이콘 → 사이트 설정 → 소리 "허용"
2. 브라우저 탭에서 한 번 클릭 후 재시도 (사용자 제스처 필요)
3. 대시보드 하단 "소리 알림" 토글 확인

#### Q: 음성 안내(TTS)가 너무 커요/작아요.

**A**: 현재 버전에서는 시스템 볼륨으로 조절해야 합니다. 향후 업데이트에서 UI 볼륨 슬라이더 추가 예정입니다.

#### Q: 푸시 알림이 안 와요.

**A**: Web Push 권한이 필요합니다.
1. 브라우저 주소창에서 알림 권한 허용
2. `.env` 파일의 `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` 설정 확인
3. HTTPS 환경에서만 작동 (로컬은 localhost 예외)

### 10.5 통계 및 리포트

#### Q: 통계 그래프가 안 보여요.

**A**: 데이터가 없거나 API 응답 지연입니다.
1. 백엔드 API 확인: http://localhost:8001/api/stats/daily
2. 최소 1일 이상 데이터 쌓여야 그래프 표시
3. PostgreSQL 연결 확인: `.env`의 `DATABASE_URL` 확인

#### Q: 리포트 생성이 너무 오래 걸려요.

**A**: 기간이 길거나 이벤트가 많으면 시간 소요됩니다.
1. 기간을 줄이세요: 90일 → 30일 → 7일
2. "이벤트 로그" 체크 해제 (용량 감소)
3. 서버 리소스 확인 (CPU, 메모리)

#### Q: CSV 내보내기 파일이 엑셀에서 깨져 보여요.

**A**: UTF-8 인코딩 문제입니다.
1. 엑셀에서 "데이터 > 텍스트 파일 가져오기" 사용
2. 파일 형식: "CSV UTF-8" 선택
3. 또는 Google Sheets에서 열기 (자동 인코딩 감지)

### 10.6 관리자 기능

#### Q: AI 모델을 변경했는데 적용이 안 돼요.

**A**: 카메라를 재시작해야 합니다.
1. 대시보드에서 "중지" 버튼 클릭
2. 5초 대기 (기존 스트림 종료)
3. "시작" 버튼 다시 클릭
4. 메트릭스 카드에서 모델 변경 확인

#### Q: Safe-Zone 폴리곤이 저장이 안 돼요.

**A**: 서버 권한 또는 좌표 형식 문제입니다.
1. 브라우저 콘솔 에러 확인 (F12)
2. 최소 3개 이상 꼭지점 필요
3. 폴리곤이 화면 밖으로 나가면 저장 불가
4. 백엔드 로그 확인: `backend/logs/app.log`

#### Q: 사용자를 삭제했는데 로그인이 돼요.

**A**: 기존 세션이 남아있는 것입니다.
1. 해당 사용자에게 로그아웃 요청
2. 관리자가 강제 로그아웃: 향후 기능 추가 예정
3. 임시 방법: `.env`의 `JWT_SECRET_KEY` 변경 (모든 세션 무효화)

### 10.7 성능 및 최적화

#### Q: CPU 사용률이 100%로 치솟아요.

**A**: AI 모델 추론 부하입니다.
1. GPU 사용 권장 (CUDA 12.x 설치)
2. AI 모델을 YOLO11n으로 변경 (가장 가벼움)
3. 프레임 레이트 낮추기: 30fps → 15fps (설정 파일 수정)

#### Q: 메모리가 계속 증가해요 (Memory Leak).

**A**: 장시간 실행 시 정상적인 현象입니다.
1. 하루 1회 재시작 권장 (새벽 시간대)
2. 이벤트 로그 자동 삭제: 90일 이상 데이터 삭제
3. 백엔드 로그 파일 정리: `backend/logs/` 폴더 정기 삭제

### 10.8 기타

#### Q: 영어로 전환하고 싶어요.

**A**: 우측 상단 지구본 아이콘 클릭 → "English" 선택. 모든 UI와 TTS 음성이 영어로 전환됩니다.

#### Q: 다크 모드로 바꾸고 싶어요.

**A**: 우측 상단 테마 아이콘 (해/달 모양) 클릭. 라이트/다크 토글됩니다.

#### Q: 시스템 로그는 어디서 확인하나요?

**A**: `backend/logs/app.log` 파일에 모든 로그가 기록됩니다. 에러 발생 시 이 파일을 확인하세요.

#### Q: 업데이트는 어떻게 하나요?

**A**: Git으로 최신 버전 pull 후 재배포:
```bash
git pull origin main
docker compose down
docker compose up -d --build
```

## 부록

### A. 용어집

| 용어 | 설명 |
|------|------|
| **YOLO11** | You Only Look Once 11세대, 실시간 객체 감지 모델 |
| **GRU** | Gated Recurrent Unit, 순환 신경망의 일종 |
| **키포인트 (Keypoint)** | 사람의 관절 좌표 (코, 눈, 어깨, 팔꿈치 등) |
| **COCO 17-point** | 17개 키포인트 표준 형식 (YOLO 출력) |
| **MediaPipe 33-point** | 33개 키포인트 확장 형식 (더 상세) |
| **Recall** | 실제 낙상 중 감지된 비율 (민감도) |
| **Precision** | 감지된 것 중 실제 낙상 비율 (정밀도) |
| **F1 Score** | Recall과 Precision의 조화 평균 |
| **False Positive (FP)** | 정상을 낙상으로 잘못 감지 (오탐) |
| **False Negative (FN)** | 낙상을 정상으로 놓침 (미검출) |
| **MJPEG** | Motion JPEG, 영상 스트리밍 프로토콜 |
| **WebSocket** | 양방향 실시간 통신 프로토콜 |
| **Canvas API** | HTML5 그래픽 렌더링 API |
| **ONNX** | Open Neural Network Exchange, 모델 표준 형식 |
| **Safe-Zone** | 안전/위험 구역 지정 기능 |
| **TTS** | Text-to-Speech, 텍스트 음성 변환 |
