# SENTIO 규칙기반 100% 전환 테스트 — 추가 조건 검토 및 적용

## 📌 배경 상황

SENTIO는 요양병원 AI 낙상감지 시스템입니다.
현재 **규칙기반 50% + ML(ONNX Transformer) 50% 앙상블**으로 작동 중인데,
GPU 없는 저사양 요양병원 PC에서 ML 추론이 병목이 되어 퍼포먼스가 떨어지고 있습니다.

**규칙기반 100%로 전환하되, 기존 4조건만으로는 부족한 인식률을 보완할 추가 조건들을 도입**하여
ML 없이도 충분한 정확도를 확보할 수 있는지 테스트하려 합니다.

---

## 🏗️ 현재 시스템 구조

```
웹캠/RTSP
  → YOLO11n-pose (사람 탐지, bbox + 17 keypoint, ~30ms)
  → ByteTrack (다중인원 ID 추적)
  → MediaPipe Pose (ROI 내 33개 관절 정밀 추출, ~15ms)
  → ★ 낙상 판정 엔진 ★  ← 여기를 개선합니다
  → 상태 머신 (SAFE → WARNING → DANGER, 3단계 에스컬레이션)
  → 알림 (WebSocket + Web Push + TTS 음성)
```

### 현재 규칙기반 4조건 (기존 코드에서 확인해 주세요)

| ID | 조건명 | 수식 | 한계 |
|----|--------|------|------|
| C1 | 머리-엉덩이 역전 | `head_y - hip_y > 0.05` | 물건 줍기/스트레칭에서 오탐 |
| C2 | 급격한 하강 | `descent > 0.15` | 빠르게 앉기에서 오탐, 느린 낙상 미탐 |
| C3 | 수평 각도 | `body_angle < 45°` | 침대 누운 환자 오탐 |
| C4 | 복합 점수 | `composite ≥ 0.5` | C1~C3 한계를 그대로 물려받음 |

### 기존 오탐 방지 7단계 필터 (유지)

```
1. 앙상블 이중 검증 → 규칙 100%에서는 "다중 조건 교차 검증"으로 변경
2. 복합 임계값 ≥ 0.50
3. 신규 인물 유예 (8프레임, ~0.5초)
4. 랜드마크 가시성 (50% 미만 스킵)
5. 착석 전용 임계값
6. 안정 누움 면제 (60프레임, ~4초)
7. 쿨다운 타이머 (DANGER 후 3초)
```

아래는 **생체역학(Biomechanics) + 물리치료 임상 근거** 기반으로 제안하는 추가 조건들입니다.

### 🔴 핵심 추가 (강력 추천) — 4개

#### N1. 수직 가속도 (Vertical Acceleration)

```
[개념]
현재 C2는 "얼마나 내려갔나(변위)"만 봅니다.
하지만 낙상의 핵심은 "감속 없이 가속되는가"입니다.

- 정상 앉기: 가속 → "감속" → 정지 (eccentric muscle control)
- 낙상: 가속만 계속됨 (제동 실패, braking failure)

이 차이를 가속도로 구분할 수 있습니다.

[PT 임상 근거]
하지체 근력 부족 환자에서 "제동 실패(braking failure)"가 
낙상의 직접 원인. Sit-to-Stand 평가에서 핵심 관찰 항목.

[의사 코드]
velocity_t     = head_y[t] - head_y[t-1]           # 현재 속도
velocity_t_1   = head_y[t-1] - head_y[t-2]         # 이전 속도
acceleration   = velocity_t - velocity_t_1          # 가속도

# 양수 = 점점 빨라짐(가속), 음수 = 점점 느려짐(감속)
if acceleration > 0.02 and velocity_t > 0.05:
    score += weight  # 감속 없는 하강 = 낙상 가능성 높음

[기대 효과]
- 오탐 감소: "빠르게 앉기"는 감속 구간이 있으므로 구분됨
- 구현 난이도: 쉬움 (기존 head_y 히스토리에 1줄 추가)
- 연산 비용: ~0.01ms (단순 뺄셈 2회)
```

#### N2. 보호 신전 반응 (Protective Extension Reflex)

```
[개념]
사람이 넘어질 때 무의식적으로 팔을 뻗어 몸을 보호합니다.
- 전방 낙상: 양손이 앞으로 뻗어짐
- 측면 낙상: 한쪽 팔이 옆으로 급격히 뻗어짐
- 후방 낙상: 양손이 뒤로 뻗어짐 (또는 엉덩이 착지)

이 반사는 정상적인 앉기/눕기에서는 절대 나타나지 않습니다.
→ 낙상에서만 나타나는 "고유 시그니처"

[PT 임상 근거]
보호 신전 반응(Protective Extension)은 낙상 위험 평가의 핵심 항목.
고령자는 이 반사가 느려 낙상 시 부상이 커짐.
Parachute Reflex라고도 불리며, 발달 평가에서도 사용.

[의사 코드]
wrist_L, wrist_R = landmarks[15], landmarks[16]  # 양손목
hip_center_y = (landmarks[23].y + landmarks[24].y) / 2

# 1) 팔이 갑자기 넓게 벌어지는 속도
arm_spread = abs(wrist_L.x - wrist_R.x)
arm_spread_velocity = arm_spread - prev_arm_spread

# 2) 손목이 엉덩이 높이 아래로 빠르게 내려가는지
wrist_drop = max(wrist_L.y, wrist_R.y) - hip_center_y

# 3) 두 조건 동시 충족 시 보호 신전 반응 판정
if arm_spread_velocity > 0.08 and wrist_drop > 0.0:
    score += weight

[기대 효과]
- 오탐 감소: 매우 높음 (이 패턴은 낙상에서만 나타남)
- 구현 난이도: 보통 (이전 프레임 arm_spread 저장 필요)
- 연산 비용: ~0.02ms
```

#### N3. 무게중심-지지면 이탈 (CoM-BoS Deviation)

```
[개념]
균형의 물리학적 정의:
  무게중심(CoM)이 지지면(BoS) 안 → 균형 유지
  무게중심(CoM)이 지지면(BoS) 밖 → 넘어짐

- 지지면(BoS) ≈ 양 발목(27, 28) 사이의 x 범위
- 무게중심(CoM) ≈ 골반 중심(23, 24의 중간점)

[PT 임상 근거]
Berg Balance Scale, Timed Up and Go(TUG) 등
모든 균형 평가의 기본 원리. 재활의학에서
"CoM이 BoS를 벗어나면 낙상"은 가장 기본적인 공식.

[의사 코드]
# 지지면(BoS) 범위
ankle_L_x, ankle_R_x = landmarks[27].x, landmarks[28].x
bos_center = (ankle_L_x + ankle_R_x) / 2
bos_half_width = abs(ankle_L_x - ankle_R_x) / 2 + 0.05

# 무게중심(CoM) 근사
com_x = (landmarks[23].x + landmarks[24].x) / 2

# CoM이 BoS를 벗어난 정도
deviation = abs(com_x - bos_center) - bos_half_width

# 벗어난 속도 (빠를수록 회복 불가능)
deviation_velocity = deviation - prev_deviation

if deviation > 0 and deviation_velocity > 0.03:
    score += weight  # 무게중심이 빠르게 지지면 이탈 중

[기대 효과]
- 오탐 감소: 높음 (물건 줍기는 CoM이 BoS 안에 머무름)
- 구현 난이도: 보통
- 연산 비용: ~0.03ms
- 주의: 한 발로 서있는 경우(single support) 처리 필요
```

#### N4. 무릎 좌굴 감지 (Knee Buckling Detection)

```
[개념]
낙상의 흔한 전조가 "무릎이 갑자기 꺾이는 것"입니다.
- 정상 보행: 무릎 각도 ~160-170° (거의 펴진 상태)
- 무릎 좌굴: 무릎 각도가 갑자기 ~90-110°로 꺾임
- 정상 앉기: 무릎 각도가 "서서히" 줄어듦

핵심은 "꺾이는 속도"입니다.

[PT 임상 근거]
무릎 좌굴은 대퇴사두근(quadriceps) 약화의 대표 증상.
Sit-to-Stand 테스트에서 가장 먼저 관찰하는 항목.
고령자 낙상의 25%가 무릎 좌굴로 시작됨.

[의사 코드]
# 무릎 각도 계산 (엉덩이-무릎-발목 3점 각도)
# 왼쪽: 23-25-27, 오른쪽: 24-26-28
def calc_angle(a, b, c):
    ba = (a.x - b.x, a.y - b.y)
    bc = (c.x - b.x, c.y - b.y)
    cos_angle = dot(ba, bc) / (mag(ba) * mag(bc) + 1e-6)
    return math.degrees(math.acos(clamp(cos_angle, -1, 1)))

knee_angle_L = calc_angle(landmarks[23], landmarks[25], landmarks[27])
knee_angle_R = calc_angle(landmarks[24], landmarks[26], landmarks[28])

# 이전 프레임 대비 변화율 (양수 = 꺾이는 중)
knee_vel_L = prev_knee_L - knee_angle_L
knee_vel_R = prev_knee_R - knee_angle_R

# 빠르게 꺾이면 좌굴
if (knee_angle_L < 120 and knee_vel_L > 12) or \
   (knee_angle_R < 120 and knee_vel_R > 12):
    score += weight

# 양쪽 동시 좌굴은 더 위험
if (knee_vel_L > 8 and knee_vel_R > 8):
    score += weight * 0.5  # 추가 가중

[기대 효과]
- 전조(pre-impact) 감지 강화 (ML 없이 전조 단계 감지 가능)
- 구현 난이도: 쉬움 (3점 각도 계산)
- 연산 비용: ~0.02ms
- 주의: 계단 오르기에서 약간 혼동 가능 → 속도 임계값으로 구분
```

### 🟡 권장 추가 — 3개

#### N5. 체간 회전 속도 (Trunk Rotation Rate)

```
[개념]
측면 낙상의 특징은 어깨 라인이 빠르게 기울어지는 것.
양쪽 어깨(11, 12)의 y좌표 차이 변화율로 감지.

[의사 코드]
shoulder_tilt = math.degrees(
    math.atan2(landmarks[12].y - landmarks[11].y,
               landmarks[12].x - landmarks[11].x))
tilt_velocity = abs(shoulder_tilt - prev_shoulder_tilt)

if tilt_velocity > 12:  # 도/프레임
    score += weight

[기대 효과] 측면 낙상 감지 정확도 향상
[연산 비용] ~0.01ms
[PT 근거] 체간 안정성(core stability) 평가의 핵심 지표
```

#### N6. 높이 궤적 패턴 (Height Trajectory Pattern)

```
[개념]
최근 15프레임(~0.5초)의 머리 높이 변화 "궤적 형태"를 분석.
- 낙상 궤적: 전반부보다 후반부가 더 빠름 (가속형)
- 앉기 궤적: 전반부보다 후반부가 더 느림 (감속형)
이를 전반부/후반부 속도 비율로 구분.

[의사 코드]
height_history = deque(maxlen=15)
height_history.append(head_y)

if len(height_history) >= 10:
    mid = len(height_history) // 2
    vel_first = height_history[mid] - height_history[0]
    vel_second = height_history[-1] - height_history[mid]
    
    # 후반부가 전반부보다 1.3배 이상 빠르면 가속형 하강
    if vel_first > 0.02 and vel_second > vel_first * 1.3:
        score += weight

[기대 효과] 앉기 vs 낙상 궤적 구분
[연산 비용] ~0.02ms (deque 연산)
[PT 근거] eccentric control (편심성 수축 조절) 유무 판별
```

#### N7. 발 위치 이탈 (Foot Displacement)

```
[개념]
발이 미끄러지거나 헛디딜 때 발목 좌표가 급격히 변화.
화장실 미끄러짐 감지에 특히 효과적.

[의사 코드]
ankle_vel_L = dist(landmarks[27], prev_landmarks[27])
ankle_vel_R = dist(landmarks[28], prev_landmarks[28])
foot_spread = dist(landmarks[27], landmarks[28])
spread_change = abs(foot_spread - prev_foot_spread)

if max(ankle_vel_L, ankle_vel_R) > 0.08 or spread_change > 0.06:
    score += weight

[기대 효과] 미끄러짐 감지, 보행 불안정 감지
[연산 비용] ~0.02ms
[PT 근거] step length variability는 낙상 예측의 중요 보행 지표
```

## 🔬 Phase 2: 추가 조건 적합성 검토

**각 조건(N1~N10)에 대해 아래 5가지 기준으로 평가해 주세요.**

```
┌─────────────────────────────────────────────────────────────────┐
```

## 🔬 Phase 3: 채택된 조건 구현

### 3-1. 구현 원칙

```
1. 기존 코드 스타일과 컨벤션을 따를 것
   - 기존 C1~C4가 사용하는 패턴(함수 시그니처, 반환 형식 등)과 동일하게 작성
   - 기존 클래스/모듈 구조 안에 자연스럽게 통합

2. 인물별(person_id) 상태 관리에 통합할 것
   - 이전 프레임 데이터(prev_velocity, prev_arm_spread 등)는
     각 인물의 상태 객체에 저장
   - 새로운 인물이 감지되면 초기값으로 리셋

3. 각 조건은 독립적으로 ON/OFF 가능하게 설계할 것
   - 설정 파일이나 환경변수로 개별 조건을 활성화/비활성화
   - 테스트 시 조건 조합을 쉽게 변경 가능

4. 가중치도 설정 가능하게 할 것
   - 각 조건(C1~C4 + N1~Nn)의 가중치를 설정 파일에서 관리
   - 조건 추가/제거 시 나머지 가중치가 자동 정규화되도록

5. 한글 주석을 상세하게 달 것
   - 각 조건의 의학적/물리학적 근거를 주석으로 설명
   - 임계값을 왜 그 값으로 설정했는지 근거 명시
   - 코딩 초보자도 로직을 이해할 수 있도록 단계별 설명
```

### 3-2. 구현 순서

```
Step 1: 기존 규칙 점수 산출 함수에 새 조건 추가
  - 기존 C1~C4 옆에 N1~Nn 함수를 추가
  - 각 함수는 0.0 ~ 1.0 사이의 점수를 반환

Step 2: 복합 점수 계산 공식 업데이트
  - 기존: composite = C1*w1 + C2*w2 + C3*w3 + C4*w4
  - 변경: composite = C1*w1 + ... + C4*w4 + N1*wn1 + ... + Nn*wnn
  - 가중치 합이 1.0이 되도록 정규화

Step 3: 오탐 방지 필터 업데이트
  - 필터 1번: "앙상블 이중 검증" → "다중 조건 교차 검증"으로 변경
    예: "최소 2개 이상의 독립 카테고리에서 높은 점수를 받아야 낙상 판정"
    카테고리: [위치/position] [동역학/dynamics] [반사/reflex] [균형/balance] [관절/joint]
  - 새 조건들에 맞는 임계값 조정

Step 4: 앙상블 가중치를 규칙 100%로 변경
  - rule_weight = 1.0, ml_weight = 0.0
  - ML 추론 함수 호출을 완전히 스킵하도록 처리
  - ONNX 모델 로딩도 생략 (메모리 절약)

Step 5: 설정 프로파일 추가
  - "규칙 확장 모드": 새 조건 포함, ML 완전 비활성화
  - "기존 호환 모드": C1~C4만 사용, 기존과 동일 동작
  - "하이브리드 모드": 새 조건 + ML 앙상블 (고사양 PC용)
```

## 🔬 Phase 4: 테스트 및 성능 비교

### 4-1. 비교할 설정 3가지

```
[A] 기존 규칙 4조건만 (Rule 100%, C1~C4만)
  → 베이스라인. 기존 ML 없이 규칙만으로 얼마나 되는지

[B] 규칙 확장 (Rule 100%, C1~C4 + 채택된 Nn들)
  → 이번에 만들 최종 결과물

[C] 기존 앙상블 (Rule 50% + ML 50%, C1~C4)
  → 현재 운영 중인 설정. B가 이것과 비슷하거나 나아야 성공
```

### 4-2. 테스트 시나리오

```
[낙상 시나리오 — 반드시 감지해야 함]
 F1. 전방 빠른 낙상 (서있다가 앞으로 넘어짐)
 F2. 후방 낙상 (의자에서 뒤로 미끄러짐)
 F3. 측면 낙상 (보행 중 옆으로 쓰러짐)
 F4. 느린 낙상 (천천히 주저앉음)          ← 기존 규칙이 놓치는 케이스
 F5. 침대 낙상 (옆으로 떨어짐)
 F6. 보행기 사용 중 낙상
 F7. 무릎 좌굴 후 낙상                    ← N4로 감지해야 할 케이스
 F8. 화장실 미끄러짐                      ← N7로 감지해야 할 케이스

[정상 시나리오 — 반드시 무시해야 함]
 N1. 정상 보행
 N2. 의자에 앉기                          ← 기존 규칙 오탐 빈발
 N3. 물건 줍기 (허리 숙임)                ← 기존 규칙 최악 오탐
 N4. 스트레칭/체조
 N5. 침대에 눕기                          ← 기존 규칙 오탐
 N6. 휠체어 이동
 N7. 빠르게 앉기 (쿵)                     ← 기존 규칙 최악 오탐
 N8. 복도 빠른 걷기
 N9. 계단 오르내리기
N10. 서서 전화통화

[전조 시나리오 — pre-impact로 감지해야 함]
 P1. 비틀거림 (넘어지진 않음)
 P2. 균형 잃었다 회복
 P3. 무릎 살짝 꺾였다 회복                ← N4로 전조 감지
```
