# SENTIO 낙상감지 앙상블 가중치 최적화 — Claude Code 에이전트 프롬프트

## 🎯 미션

당신은 SENTIO 요양병원 낙상감지 시스템의 **AI 파이프라인 최적화 전문가**입니다.
현재 시스템의 낙상감지 파이프라인은 **규칙기반(Rule-based) 50% + ML(ONNX Transformer) 50% 앙상블**으로 작동 중이나, 저사양 하드웨어(GPU 없는 요양병원 PC)에서 **퍼포먼스가 떨어지는 문제**가 발생하고 있습니다.

최적의 **규칙/ML 가중치 조합**을 찾아 퍼포먼스와 인식률의 균형을 달성해 주세요.

### Phase 3: 벤치마크 스크립트 작성

아래 5가지 가중치 조합을 테스트하는 벤치마크 스크립트를 작성해 주세요:

| 조합 | 규칙(Rule) | ML | 목적 |
|------|-----------|-----|------|
| A | 100% | 0% | 규칙 단독 (최고 속도, ML 추론 완전 생략) |
| B | 70% | 30% | 규칙 중심 (속도 우선, ML 보조) |
| C | 50% | 50% | 현재 설정 (베이스라인) |
| D | 30% | 70% | ML 중심 (정확도 우선) |
| E | 0% | 100% | ML 단독 (최고 정확도, 규칙 생략) |

```python
# 벤치마크 스크립트가 측정해야 할 항목:

# ── 1. 속도 지표 ──
# - 프레임당 처리 시간 (ms) — 평균, P50, P95, P99
# - 초당 처리 프레임 수 (FPS)
# - 규칙기반 추론 시간 단독 측정
# - ML(ONNX) 추론 시간 단독 측정
# - 전체 파이프라인 시간 (YOLO → MediaPipe → 앙상블 → 판정)

# ── 2. 인식률 지표 ──
# - 재현율(Recall): 실제 낙상 중 감지 비율 (가장 중요! 놓치면 환자 위험)
# - 정밀도(Precision): 낙상 판정 중 실제 낙상 비율
# - F1 Score: 재현율과 정밀도의 조화평균
# - 오탐률(FPR): 정상인데 낙상으로 잘못 판정한 비율
# - 미탐률(FNR): 실제 낙상을 놓친 비율

# ── 3. 시나리오별 성능 ──
# 아래 시나리오에서 각 조합이 어떻게 판단하는지 확인:
# [낙상] 전방 빠른 낙상, 후방 느린 낙상, 측면 낙상, 의자에서 미끄러짐
# [정상] 물건 줍기, 빠르게 앉기, 스트레칭, 침대에 눕기
# [전조] 비틀거림, 균형 상실 후 회복

# ── 4. 리소스 지표 ──
# - CPU 사용률 (%)
# - 메모리 사용량 (MB)
# - ONNX 모델 로딩 시간
```

### Phase 5: 최적 조합 추천 및 구현

```
1. 아래 우선순위에 따라 최적 조합을 추천해 주세요:
   (의료 현장 특성상 우선순위가 일반 시스템과 다름!)

   🥇 1순위: 미탐률(FNR) = 0에 가까울 것
      → 실제 낙상을 절대 놓치면 안 됨 (환자 생명 관련)

   🥈 2순위: 저사양 PC에서 실시간 처리 가능할 것
      → GPU 없는 요양병원 PC에서 최소 10 FPS 이상

   🥉 3순위: 오탐률(FPR)이 적절할 것
      → 오탐이 너무 많으면 알림 피로(Alert Fatigue)로
        간호사가 알림을 무시하게 됨

2. 추천 조합을 실제 코드에 적용하는 방법을 제시해 주세요:
   - 설정 파일 변경 (config/settings)
   - 또는 환경변수로 런타임 조절 가능하게
   - A/B 테스트를 위한 동적 전환 기능

3. 가능하다면, 조합을 "프로파일"로 만들어 주세요:
   - "고속 모드" (규칙 중심, 저사양 PC용)
   - "균형 모드" (현재 50/50)
   - "정밀 모드" (ML 중심, 고사양 PC용)
   → 관리자 설정에서 선택 가능하도록
```
